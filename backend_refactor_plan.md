| Layer / Area                    | What should belong here                                                                                            | Why it belongs there                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **State / Config / Constants**  | Database path, snapshot path, status values, and possibly current student information                              | These are shared values, not database actions. Keeping them separate makes it clearer what the rest of the program depends on. |
| **Database Layer**              | Connecting to the database, creating tables, and basic queries like finding courses or enrollment records          | This layer should focus on storing and retrieving data. It should not decide larger enrollment rules.                          |
| **Service Layer**               | Enrollment actions, unenrollment actions, student summaries, and decisions about what counts as active or inactive | This layer should contain business rules, such as how enrollment works and what status changes mean.                           |
| **Seed / Setup Logic**          | Sample courses and sample enrollment records                                                                       | Seed data is only for preparing the practice database, so it should be separate from normal app behavior.                      |
| **Snapshot / Export Logic**     | Collecting database records and writing the JSON snapshot                                                          | Exporting is its own responsibility because it combines data from multiple places and writes it to a file.                     |
| **Main Runner / Orchestration** | Calling setup, showing sample behavior, running the demo flow, and triggering export                               | The runner should coordinate the program without owning database rules or service rules.                                       |

Overall, the plan should be to separate the code by responsibility. The database layer should handle data access, the service layer should handle enrollment decisions, config should hold shared constants, setup should prepare sample data, export should handle snapshots, and the runner should only coordinate the flow. This would make the design easier to understand, test, and expand later.
